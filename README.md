## 深度案例（更新至2026-10-27）

当前142例中142例已增加逐项研究：原有问题、工程师介入、技术方案、业务提升和未披露信息。每条区分公开事实、分析建议和未披露。详见 [案例全文](CASES.md)。

## 案例研究与验收标准

每个案例须查阅完整原始资料，并追查相关客户公告、技术说明、工程访谈或演示；不得仅凭搜索摘要或一句客户宣传完成收录。公开资料的可得性不同，不能保证取得企业未披露的内部材料。

逐项检查并在可读全文中写明：
1. 公司、国家、行业及项目实际落地区域。
2. 介入前的问题、原有流程、痛点影响和可核验基线。
3. FDE（Forward Deployed Engineer，前线部署工程师）身份依据、职责、客户参与者与实施过程。
4. 数据输入、处理流程、模型、检索、工具、系统接口、权限、人工复核与异常处理；只将项目资料明确披露的部分称为真实技术方案。
5. 试点、上线、采用范围、持续评测、维护与回滚的已披露情况。
6. 实际解决了什么、未解决什么；成本、效率、质量和商业收益分别列出分母、时间窗及证据。没有数据时明确未披露。
7. 总投入、运行费用及净收益不互相混用；愿景、预测和其他产品成效不能当项目已实现结果。
8. 风险、权衡、可复用方法与关键技能；分析建议必须与企业事实分开。
9. 逐项来源链接与核验日期。相互矛盾或信息不足处明确列出，不用猜测填空。

GitHub 的 CASES.md 必须展开研究详情，不能只有摘要或把完整内容只放在 JSON。补查以修订现有案例进行，不重复计作新增。记录可继续完善；基础版与已深化案例明确标记，不宣称未知资料已获取。
